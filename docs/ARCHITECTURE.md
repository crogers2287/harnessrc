# Architecture and event protocol

One gateway process uses SQLite WAL (`synchronous=FULL`) and a versioned migration. Native code resides in adapters, not React or generic HTTP handlers. A Herdr client consumes documented newline-delimited Unix-socket JSON requests and subscriptions; periodic authoritative snapshots recover dropped lifecycle notifications. Native conversation sources are allowlisted transcript roots, a Hermes SQLite database, an OpenCode HTTP endpoint, or the private Codex bridge socket.

Session identity is a hash of host, harness and native session ID. Pane movement does not duplicate a session. The owner generation also captures Herdr terminal identity and shell/foreground process-group IDs. Control validates the current native ID, terminal identity, process identity and stored generation. Duplicate live claims disable safe ownership. Hosts are represented independently; multiple reachable local/forwarded socket installations can be configured. Secure cross-host socket transport/host enrollment is not provisioned automatically.

Each normalized event has durable global sequence, session ID, source ID, source name, timestamp, native session ID, optional turn ID, kind and validated data. SQLite uniqueness on session/source ID prevents duplicate replay. Native transcript UUIDs and item IDs are preserved where available. Source order supplies tie-breaking; the gateway sequence defines replay order. Readers process complete JSONL lines, buffer partial UTF-8 records and reject roots/symlinks outside configured paths. Existing supported records are imported before appended records. No guessed reasoning is emitted. Raw transcripts are not copied into the gateway; redacted normalized payloads support debugging while minimizing secrets.

Event kinds cover user/assistant messages and deltas, summaries, tools, file/diff activity, questions, approvals, plans, progress/status, subagents, turns, tasks and connection state. A declared kind does not imply that every adapter can emit it. HTTP event pagination uses durable sequence cursors; WebSockets send authorized invalidations and clients fetch authoritative state. Reconnect refetches cached queries without creating new turns.

The broker records native request ID, exact session/generation/turn, prompt, choices, schema, expiry and route. Answer submission validates authorization, ownership, schema, pending status and lease before atomic claim. Concurrent submissions cannot both reach the native route. A lost confirmation is `uncertain`, never blindly retried. Claude hook decisions require hook acknowledgement. Native Codex JSON-RPC replies preserve the original request ID; no generic chat response is substituted.

Tasks have immutable IDs and client idempotency keys, native session/generation, prompt/attachments, order, timestamps, eligibility, attempts, execution correlation and status. Claiming is atomic; one dispatcher runs per session. Unresolved interactions, paused queues, active turns and uncertain predecessors block dispatch. Restart marks in-flight delivery uncertain and reconciles through the native bridge task ledger. Owner changes prohibit delivery; no automatic retry when the owner cannot prove receipt. Pending CRUD and history survive restart.

The Codex bridge is a standalone process launched inside Herdr. Herdr supervises that process; the bridge owns one documented app-server stdio connection. Its SQLite ledger survives gateway restarts, and the phone owns neither connection. Installed Codex JSON schemas determine native capabilities. Unsupported server requests block without guessed approval. Bridge-process restart can leave previous executions uncertain; operator reconciliation is required.

Only the public offline fallback is cached; authenticated API responses, transcripts and tokens are not placed in service-worker caches. Cookie authentication is shared between HTTP and WebSockets. Browser scrolling uses virtualized event rows, pagination and per-session restoration.
